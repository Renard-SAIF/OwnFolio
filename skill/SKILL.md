# 投资项目记录台

给一级市场投资人用的项目记录与分析能力。核心不是"记下来"，是**事后校准**：
半年后回看，你当初的判断到底准不准。

## 你的角色分工

- **AI负责**：读材料、理解语义、提取字段、写横评结论、写胶囊叙述
- **脚本负责**：一切计算与渲染（命中率、均值、图表、HTML），**必须调脚本，不许自己心算或手写图表**
- **绝不**：自己实现飞书/钉钉的接口调用。读写表格一律委托平台已有能力（见references/storage-adapters.md）

## 第0步：先确认项目库在哪（每次会话必做）

**先读 `references/current-library.md`。**

- **读到了** → 里面记着用户指定的项目库位置，直接用，**不要再问第二遍**。
- **文件不存在**（第一次用）→ 走下面的提问流程；问清楚之后，照
  `references/current-library.example.md` 的格式**新建 `current-library.md`** 把位置记下来。
  这个文件含有用户的表格令牌，已被 `.gitignore` 排除，**不要提交到公开仓库**。
- **用户本轮明确说要换库** → 走提问流程，旧位置挪到新文件的"历史"一节。

**如果用户没有明说项目库在哪，必须先问，不要猜、不要自己新建一个。**

问法（一次问清，别挤牙膏）：

> 你的项目库放在哪里？三种都支持：
> 1. 飞书多维表格（给我表格链接或app_token）
> 2. 钉钉AI表格 / 在线表格（给我表格链接）
> 3. 本地Excel / CSV文件（给我文件路径）
>
> 如果你还没有项目库，我可以帮你建一个标准表头的空库。

问到之后，**记在本轮上下文里**，后续所有读写都用它，不要再问第二遍。

建新库：`python scripts/init_sheet.py --out <路径>`（会同时建好两张表，见下）

## 数据结构：两张表

| 表 | 每行含义 | 谁写 |
|---|---|---|
| **项目库**（主表） | 一个项目一行，存**现状** | 首次录入时新增；后续只改这一行 |
| **看法流水**（流水表） | 一条**追加**记录，某个时点你对这个项目的看法 | 每次看法有变就追加一行，**永不改旧行、永不删** |

字段定义见 `references/schema.md`，表头模板见 `assets/headers-main.csv`（主表）与 `assets/headers-log.csv`（流水表）。

### 追加规则（用户明确要求，不可违反）

用户十月一号聊完有个看法，十一月看法变了——**十月一号那条必须原样留着**，
十一月的新看法**追加一行**，而不是覆盖。

含义：
- 主表那行的"我的看法"同步更新为最新（方便一眼看全貌）
- 流水表**追加**一行，写清时点、当时的看法、当时的兴趣度、当时的预测
- 旧行一个字都不许改——这就是时间胶囊和打脸清单的命根子

回填：后来结果出来了（中了/没中），只回填**那一行**的 `result` / `missReason` 字段，
其余字段保持原样，等于给历史打了分。

## 三条工作流

### A. 录入新项目

输入：BP、会议纪要、一段口述、或一份文档。

1. 读 `references/extraction-prompt.md`，按里面的规范提取字段
2. **必填项缺了就问用户**，不要自己编（公司名、行业、轮次、状态、来源、兴趣度、一句话逻辑）
3. 主表新增一行
4. 流水表追加第一行（`at` = 交流日期，`view` = 我的看法，`expect` = 当时的预测）
5. **顺手刷新看板**：重新生成到**同一个文件**，覆盖旧的

   看板文件路径约定（第一次问用户要一次，之后记住）：
   - 默认放项目库同级目录，文件名 `投资看板.html`
   - 本地Excel方案：跟xlsx放一起
   - 飞书/钉钉方案：问用户想放本地哪里（云端表格本身不放HTML）

   **覆盖而不是新建**，这样用户随时打开那个文件都是最新的，也不会堆一屋子HTML。

### B. 更新看法

用户说"我对XX项目的看法变了" / 又聊了一次 / 有新材料：

1. 主表那个项目的行：更新 `myView`、`score`、`status`、`updatedAt`
2. 流水表**追加一行**：`at` = 今天或新的交流日期，`view` = 新看法，`expect` = 新预测，
   如果上次预测已有结果，**顺手回填上一行的 `result`**
3. 不要动任何旧行
4. 顺手把看板重新生成一遍（覆盖同一个文件）

### C. 生成看板

用户说"出个看板" / "看看我的项目库" / "做个横评" / "回看一下"：

1. 读**全量**数据（主表 + 流水表），不要抽样
2. 转成标准格式（见references/schema.md的JSON结构）
3. 跑脚本：`python scripts/render_dashboard.py --data <标准JSON> --out <输出.html>`
4. 交付HTML文件，并**用一两句话点出你从数据里看到的结论**（脚本算数，你解读）

看板是**快照**：数据已经烤进HTML，双击就能看、能转发、离线可用、不用装任何东西。
数据更新了就重新生成一份。

## 铁律

1. **绝不编数据**。材料里没有的字段就空着或问用户，不许推测填充。
   （投资人靠这个做决策，编一个估值会害死人）
2. **计算交给脚本**。命中率、均值、分布、图表——一律 `render_dashboard.py` 算，
   不许自己心算或手写SVG。
3. **看板零依赖**。生成的HTML不引任何外部框架/字体/图表库，图标和图表全内联SVG，
   不用emoji。
4. **历史不可改**。流水表只追加、只回填，不覆盖、不删除。
5. **不碰任何密钥**。不在任何文件里写死通行证、接口地址、账号。
6. **敏感数据提醒**：如果项目库在飞书/钉钉在线表格里，涉及未公开估值、
   创始人个人信息时，提醒用户一句数据存在哪。
7. **看板为空时不要编假数据**，显示引导语即可（可以加 `--demo` 生成示例看板给用户看效果）。
