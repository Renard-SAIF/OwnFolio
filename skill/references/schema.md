# 投资项目标准字段

任何读写操作前先看这份。字段名的**英文**是唯一标准，中文只是给人看的标签——
用户表格里的列名可能千奇百怪（"公司名"/"项目名称"/"标的"），都要映射到英文标准名。

## 表一：项目库（主表，一个项目一行，存现状）

| 英文 | 中文 | 必填 | 说明 |
|---|---|---|---|
| `company` | 公司名称 | ✅ | 唯一标识，判定"同一个项目"靠它 |
| `industry` | 行业标签 | ✅ | 见下方枚举，可自定义 |
| `round` | 融资轮次 | ✅ | 见下方枚举 |
| `status` | 决策状态 | ✅ | 见下方枚举 |
| `sourceType` | 项目来源 | ✅ | 见下方枚举 |
| `sourceDetail` | 来源明细 | | 哪个机构/哪个人/哪个会议，跟着来源走 |
| `score` | 兴趣度 | ✅ | 1-5，5最高。**存最新值** |
| `thesis` | 一句话投资逻辑 | ✅ | 一句话，别写成一段 |
| `meetDate` | 交流日期 | | YYYY-MM-DD |
| `attendees` | 对方参会人及角色 | | |
| `product` | 产品与技术 | | |
| `competitors` | 竞争对手与差异点 | | |
| `revenue` | 收入与财务 | | |
| `financing` | 本轮融资与估值 | | |
| `credibility` | 信息可信度 | | 创始人自述 / 部分验证 / 已验证 |
| `myView` | 我的看法 | | **存最新看法**；历史去流水表看 |
| `concernResult` | 当初的预测应验了吗 | | 未验证 / 中了 / 没中 / 还没发生，默认"未验证" |
| `missReason` | 为什么没中 | | 只在"没中"时填 |
| `dropReason` | 放弃原因 | | 只在"已放弃"时填 |
| `nextFollow` | 下次跟进日期 | | YYYY-MM-DD，看板的"该跟进了"靠它 |
| `createdAt` | 建档时间 | | 自动 |
| `updatedAt` | 最后更新 | | 自动 |

## 表二：看法流水（追加式，一条一次，永不改旧行）

| 英文 | 中文 | 必填 | 说明 |
|---|---|---|---|
| `company` | 公司名称 | ✅ | 关联到主表 |
| `at` | 时点 | ✅ | YYYY-MM-DD，这次看法形成的日期 |
| `stage` | 当时阶段 | | 当时的决策状态 |
| `score` | 当时兴趣度 | | 1-5 |
| `view` | 当时的看法 | ✅ | **原话**，不要润色 |
| `expect` | 当时的预测 | | 我预计会发生什么。这是打脸清单的原料 |
| `result` | 后来的结果 | | 中了 / 没中 / 还没发生。**后来回填**，不删改其余字段 |
| `missReason` | 为什么没中 | | 回填 |
| `source` | 来源 | | 哪次会议 / 哪份材料 |

## 枚举值（照抄，别自创）

- **决策状态status**：初次接触 · 持续观察 · 深度尽调 · 已过投委会 · 已出投资意向书 · 已投 · 已放弃
- **项目来源sourceType**：融资顾问推送 · 已投公司推荐 · 朋友介绍 · 主动挖掘 · 行业会议 · 其他
- **兴趣度score**：5 · 4 · 3 · 2 · 1
- **应验结果concernResult / result**：未验证 · 中了 · 没中 · 还没发生
- **信息可信度credibility**：创始人自述 · 部分验证 · 已验证
- **融资轮次round**：种子轮 · 天使轮 · Pre-A轮 · A轮 · A+轮 · B轮 · B+轮 · C轮 · C+轮 · D轮及以后 · Pre-IPO轮 · 并购轮 · 其他
- **行业标签industry**（默认词表，可加）：AI应用 · 具身智能 · 机器人零部件 · 半导体 · 生物医药 · 医疗器械 · 新能源 · 新材料 · 企业软件 · 自动驾驶 · 低空经济 · 商业航天 · 量子计算 · 可控核聚变 · 脑机接口 · 消费 · 金融科技 · 跨境电商 · 其他

自创新值时注意：**"其他"永远排在最末一位**，新赛道插在它前面。

### 容错规则（很重要）

用户的表格是手动维护的，脏数据一定会有。读进来时按这套清洗：

- 字段缺失 → 填空串，不要报错
- `score` 不是1-5的数字 → 当空值处理，不计入均值
- 日期格式乱（"2026/9/1"、"9月1号"）→ 尽力归一到YYYY-MM-DD，识别不出就留原值
- 枚举值对不上（比如状态写成"在看"）→ **保留原值**，在看板里归到"其他"，
  **不要擅自改成标准值**（可能那是有意义的新阶段，要问用户）
- 同一个company在主表出现两行 → 保留 `updatedAt` 最新的那行，并提醒用户
